# 单视图采集与会话管理

当前默认连接本地摄像头服务，主检测与样本采集共用 `http://127.0.0.1:8765`。
摄像头由 Python 服务持有，界面接收共享预览并提交单视图采集请求。
默认无摄像头图像时显示空白和连接提示，不加载模拟图。设备、请求模式和 ROI
通过服务启动配置选择；品牌标签描述配置来源，设备索引不构成型号识别。
导航名称为“样本采集 / Sample capture”，保留原有布局与六角度、两照明单独采集流程。

## 摄像头连接与证据

- 工作台打开时每两秒请求健康状态；仅当 `camera.connected` 与
  `camera.capture_available` 均为真时允许摄像头采集。连接失败、旧帧或恢复过程
  禁止采集；服务同时在采集时重新检查，避免前端状态延迟导致旧帧入库。
- 预览来自 `/api/stream.mjpg`；“重试连接”调用 `POST /api/control/reconnect`。
  不使用浏览器 `getUserMedia`，无需浏览器摄像头权限。
- `image_size_px` 来自已经取得的图像；无帧时为 `[0,0]`，有效请求配置下显示“等待首帧”。
  `camera.requested_mode` 单独显示请求尺寸、格式和帧率，不充当已取得图像的尺寸。
- 手动调整角度与照明后直接点击采集。当前照明来源为 `manual`、
  `operator_declared`，不生成硬件 READY/OFF 确认。不会重复要求确认角度或照明；
  重拍与删除仍有对应的确认。
- 实际摄像头会话标记 `LIVE_INTEGRATION_ONLY`；故障注入测试保留其测试证据等级。
  旧离线服务须显式使用 Week 7 启动器，其 `OFFLINE_SYNTHETIC_ONLY` 标签及独立归档
  继续保留。毫米尺寸与位置未测量，物理输出未启用。

## 操作

1. 创建会话只建立样本记录，不拍摄图像。也可从左侧恢复已有会话。
2. 选择角度及明场或暗场，手动调整后点击对应的采集按钮。每次只保存一个视图的
   原图和标注图，按钮名称随所选照明更新。
3. 保存反馈指明本次角度和照明。可点击“选择下一待补视图”，或直接选择矩阵中的
   缺图格子；目标不会在保存后自动切换。点击已保存格子查看原图。
4. 重拍须确认具体视图。它保留原始尝试，并且不更改同角度的另一照明视图。
5. 十二个视图齐全后检查图像、完成样本；主区与侧栏同步显示完成，采集锁定。
6. 会话右侧垃圾桶仅删除相应会话。确认框列出样本名称和完整会话 ID，说明会
   永久移除该会话的记录、候选、事件及所有历史原图/标注图。取消不发送请求。

删除失败时保留列表与错误。若数据库删除完成但文件被占用等原因导致清理未完成，
页面明确显示待清理状态和重试按钮；刷新页面后该入口仍可从服务恢复。
删除当前会话会清空查看区，删除其他会话保留当前选择。

## 接口与恢复

`POST /api/week7/samples/{session_id}/capture` 必须带单个照明模式：

```json
{"angle_deg":60,"lighting_mode":"dark_field","retake":false}
```

省略或使用未知 `lighting_mode` 返回 422，不生成图像。旧脚本仍能显式调用
`capture_angle` 双视图兼容方法，交互界面和 HTTP 采集使用 `capture_view`。

`DELETE /api/week7/samples/{session_id}` 返回会话 ID 和已删除记录/图像数量。
完整删除返回 200；待清理返回 202、`cleanup_pending:true` 和剩余数量。
`GET /health` 的 `pending_deletions` 提供可重试 ID；同 ID 的 DELETE 重试文件清理。

文件先在同一归档根目录暂存重命名，再提交数据库删除。数据库事务/提交失败会
还原目录；进程中断后可按同一会话 ID 恢复或重试。新增的
`sample_deletion_cleanup` 表只保存待清理工作，不改写已有样本记录。
删除与采集共用工作流锁；跨会话文件引用、越界路径及目录链接会被拒绝。
